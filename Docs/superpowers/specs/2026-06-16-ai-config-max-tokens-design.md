# AI 配置 `max_tokens` 校验调整设计

## 背景

当前 AI API 配置中的 `max_tokens` 在前端被限制为 `1-32000`。用户需求是取消上限，只要求该字段为正整数即可。

现状问题：

- 前端 `validateConfig()` 写死了 `32000` 上限。
- 后端当前没有统一的“正整数”约束，前后端口径不完全一致。
- 如果仅改前端，不足以防止绕过前端直接写入 `0`、负数或非整数值。

## 目标

- 取消 `max_tokens` 的上限限制。
- 前后端统一为“可选字段；如果传值，则必须是正整数”。
- 保持数据库结构不变。
- 尽量减少对现有调用链的影响。

## 方案

采用方案 B：

- 前端移除 `32000` 上限校验。
- 前端错误提示改为“最大token数必须是正整数”。
- 后端为 AI 配置创建/更新 schema 增加正整数校验。
- 不修改数据库字段类型，仍使用整数类型。

## 影响范围

- 前端：
  - `frontend/src/services/aiConfig.ts`
  - `frontend/src/pages/SystemConfig.tsx`（只核对输入行为，原则上不做额外复杂改造）
- 后端：
  - `app/schemas/video.py`

## 数据规则

- `max_tokens` 可为空。
- `max_tokens` 若有值，必须满足：
  - 是整数
  - 大于 0
- 不设置最大值上限。

## 错误处理

- 前端在提交前拦截非法值，给出明确中文提示。
- 后端 schema 继续作为最终兜底，返回校验错误，避免非法数据入库。

## 测试

- 前端：补充或更新校验测试，覆盖“超大整数允许通过”“0/负数/非法值拦截”。
- 后端：补充 schema/接口相关测试，覆盖“正整数通过，非正整数失败”。

## 非目标

- 不修改 AI 调用时默认 `4000` 的兜底逻辑。
- 不处理不同模型厂商自身的 token 上限差异。
- 不新增数据库迁移。
