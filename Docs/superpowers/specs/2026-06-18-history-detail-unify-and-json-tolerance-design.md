# 2026-06-18 解析历史详情入口合并 + 时间行自适应 + JSON 兼容增强

## 目标

- 解析历史列表中，将 `查看` 与 `解析结果打标` 合并为同一个入口按钮。
- 详情弹窗中的 `创建时间 / 完成时间` 行去掉不必要的宽度限制，避免有剩余空间却提前折行。
- 继续增强“解析结果打标”后端 JSON 解析兼容性，减少模型输出轻微不规范时的失败率。

## 方案

### 1. 历史列表入口合并

- 历史列表只保留一个按钮：`查看 / 打标`
- 点击后统一打开同一个详情弹窗
- 详情弹窗内仍包含：
  - 基本信息
  - 当前标签
  - 解析结果打标面板
- 不改变“手动触发打标”的规则：
  - 进入详情不自动调用 LLM
  - 只有点击 `生成候选标签 / 重新生成` 才触发

### 2. 时间行布局调整

- 去掉 `创建时间`、`完成时间` 项目的固定宽度约束
- 改为自适应布局，优先单行显示
- 仅在空间确实不足时再自然换行

### 3. JSON 兼容增强

- 在现有已支持的代码块/包裹文本提取基础上，继续增强以下兼容：
  - 去除常见前后说明文字
  - 容忍 Markdown 包裹
  - 容忍轻微不规范的 JSON 外层包装
- 若仍解析失败：
  - 记录有限长度的原始响应片段到后端日志，便于排查
  - 前端继续展示安全错误信息，不直接暴露敏感响应体

## 非目标

- 不新增独立详情页路由
- 不改变“当前标签结果唯一归并到视频维度”的业务规则
- 不引入新的数据库结构

## 测试

- 前端：
  - 历史列表仅存在 `查看 / 打标` 按钮
  - 点击后正常打开详情
  - 时间信息区域在测试快照/断言中不再依赖固定宽度类
- 后端：
  - 补充“非严格 JSON”提取/修正用例
  - 确保合法候选标签仍可正常解析
